# 小说生成模块 Prompt 设计

> 配套文档：`implementation-plan.md`。所有 prompt 模板集中在 `src/server/module/novel/prompts.ts`，以函数形式按 `kind` 导出，便于调优。
> 原则：结构化但字段少、允许留空；约束走向（符合用户心意），放开笔法（模型创造力）。

## 1. 通用系统提示（system）

所有生成任务共用一份基底系统提示，按任务附加段落：

```
你是一名中文网络小说作家，擅长成人向言情小说，文笔直白流畅，重视感官细节与人物情绪的刻画。
- 严格使用简体中文写作
- 严格遵循用户提供的大纲与设定，但具体措辞、场景展开、对话内容由你发挥
- 不要输出任何与小说无关的内容（不要解释、不要总结、不要加章节外的备注）
- 不要复述或引用本提示词中的任何说明文字
```

尺度相关的措辞由用户在自己的要求里掌握，系统提示不写规避或诱导内容。

## 2. 生成核心设定（kind: setting）

```
【参考材料】（每篇参考文一段，如有勾选）
===
《{ref.title}》
{ref.content}   // 存储内容（可能已截断为末尾 50k）
===

【任务】
参考上述材料，按以下要求产出一份核心设定：
{用户要求}

要求：
- 只产出设定本身，不要写故事
- 篇幅控制在 800 字以内
- 若要求涉及角色，用条目列出：姓名 / 外貌 / 性格 / 与其他角色的关系
- 若要求涉及世界观或故事基调，分小节陈述
```

说明：参考文上传多篇时拼接进同一 user 消息；总量受 `REF_TOTAL_MAX_CHARS` 约束，不会爆上下文。

## 3. 生成章节大纲（kind: outline）

```
【核心设定】（勾选的设定卡片全文，逐张拼接）
【前情摘要】（summaryChapterIds，每章一条：第{n}章：{summary}）
【最近章节全文】（fullChapterIds，完整正文）

【任务】
为第 {nextIndex} 章设计大纲。输出 JSON（不要输出其他内容）：
{
  "beats": ["节拍1", "节拍2", ...],   // 4-8 条，每条一句话，按顺序描述关键情节点
  "tone": "本章基调与目标，一句话",
  "taboos": "本章不要发生的事，一句话，可为空字符串"
}

要求：
- 节拍只写「发生什么」，不写「怎么写」；把描写空间留给正文
- 与前文的角色关系、状态保持连续
- {用户附加要求，如有}
```

大纲用 JSON 输出而不是自由文本：前端要解析成可逐条编辑的节拍列表。解析失败时自动重试一次，再失败把原文展示给用户手动修。

「按指令微调大纲」（revise-outline）在同一 prompt 上追加：

```
【现有大纲】{outline JSON}
【修改指令】{用户指令}
只按修改指令调整，其余节拍保持不变，仍输出完整 JSON。
```

## 4. 生成章节正文（kind: content）

```
（核心设定 / 前情摘要 / 最近章节全文 / 参考文节选，同 4.1 消息结构）

【本章大纲】
基调：{tone}
节拍：
1. {beat1}
2. {beat2}
...
禁区：{taboos}

【任务】
按大纲写作第 {index} 章正文。
- 严格按节拍顺序推进，不跳过、不提前剧透后续节拍之外的情节
- 每个节拍充分展开：动作、对话、心理、感官细节，不要一笔带过
- 目标篇幅 {targetLength} 字左右（用户可在要求中调整，默认 3000）
- 违反「禁区」中列出的内容
- 直接输出正文，不要输出章节号、标题或任何说明
```

注意 taboos 那行实际是「不得违反」——最终文案以实现时测试效果为准，负面约束的措辞对模型行为影响大，需在联调时验证。

**续写（continue-content）**：正文作为已有前缀给出，指令改为「从下文结尾处无缝续写，不要重复已有内容：…{已有正文末尾 2000 字}」。上游接口支持时优先用 prefix/续写能力（DeepSeek 的 `prefix` 参数或 beta FIM），否则退回消息内拼前缀。

**重写选中段落（rewrite-selection）**：

```
【正文全文】{content}
【需要重写的段落】（第 {a} 至 {b} 段）
{selection}
【修改指令】{用户指令}
只输出重写后的段落文本（保持与上下文衔接），不要输出其余部分。
```

## 5. 生成章节摘要（kind: summary，非流式）

```
【章节正文】{content}

【任务】
为以上章节写一段供后续续写使用的摘要，200-400 字，必须覆盖：
- 发生的关键事件（按顺序）
- 角色关系/态度发生的变化
- 新出现的设定、名词、道具
- 结尾时各角色的位置、情绪与未解决的悬念
只输出摘要文本。
```

摘要是给模型看的「续写一致性备忘录」，不是给读者的简介——prompt 里明确这一点，避免生成宣传文案式的内容。

## 6. 调优备忘

- `temperature`：正文 0.8-1.0（创造力），大纲 0.7，摘要 0.3（保真），设定 0.8；做成 constants 便于调
- 大纲 JSON 若被模型包在 ```json 代码块里，解析前先做 markdown 剥离
- 若正文频繁「跳过节拍直接收尾」：在大纲 prompt 中限制节拍数 ≤ 8，并在正文任务里加「写到节拍 k 为止，不要收束全书」
- 若模型复述大纲原文：在正文任务加「不要使用大纲中的原句」
- 以上两条是常见病症，联调时优先验证
