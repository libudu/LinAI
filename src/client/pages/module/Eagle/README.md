# Eagle 图片管理模块

浏览 Eagle 资源库（`.library`）中的图片、GIF 和视频，支持目录导航、搜索排序、预览、条目编辑、回收站、HEIC/HEIF 转换与 AI 图片/视频整理。本应用的配置、缓存和任务存放在 `data/eagle/`；编辑、回收站操作、格式转换、分类确认、递归仅重命名与视频联系表保存会写入 Eagle 库。

## 数据与索引

```text
<库>.library/
├── metadata.json            # 嵌套目录树
├── mtime.json               # { 条目ID: lastModified } 修改指纹
└── images/<id>.info/
    ├── <name>.<ext>          # 原文件
    ├── <name>_thumbnail.png  # Eagle 缩略图（可能不存在）
    ├── metadata.json        # 属性、folders[]、isDeleted
    └── linai/               # 视频联系表，按需生成，不参与启动扫描
        ├── video-contact-sheet.webp
        └── video-contact-sheet.json # 源文件指纹、时长、采样、版本与图片校验值
```

条目归属记录在条目 metadata 的 `folders[]`，目录自身不保存成员列表。

| 数据                               | 存储方式 / 位置                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 库路径、视觉接入点                 | SettingsRegistry：`eagle` / `eagle-vision`                                                                                            |
| 目录展开、手动分类历史             | 通用集合 `eagle.folder-tree` / `eagle.manual-folders`，固定 `preferences` 条目；`data/eagle/folder-tree.json` / `manual-folders.json` |
| 整理任务、结果                     | 私有 DocumentStore / EntityStore：`data/eagle/organize/task.json`、`items/<itemId>.json`                                              |
| 可重建缓存                         | `data/eagle/index-shards/`、`thumb/`                                                                                                  |
| 视频长期预览联系表                 | Eagle 库内 `images/<id>.info/linai/video-contact-sheet.{webp,json}`                                                                   |
| 排序、展示选项、媒体类型、选中目录 | localStorage，经 `preferences.ts` 管理                                                                                                |

偏好模型由前端拥有，任务模型由服务端 `organize/model.ts` 拥有；旧数据在存储边界归一化，旧目录展开记录仅在迁移写入成功后删除。

- 启动优先恢复 32 个索引分片，无缓存时全量扫描；首次查询始终等待启动校验完成，不提前展示未校验缓存。启动校验与手动刷新按 `mtime.json` 和目录列表增量扫描；Eagle 指纹缺失时比较 LinAI 索引中记录的元数据文件修改/状态变更时间、大小与条目目录修改/状态变更时间，属性变化或本地校验信息缺失时才回读元数据、探测文件名。旧缓存首次扫描补齐本地校验信息，读取期间属性变化则不记录，下一次重新校验；本地信息不写入 Eagle 的 `mtime.json`。外部 Eagle 改动需手动刷新，目前无文件监听，应用写锁不约束外部客户端。
- 重读后比较实际索引投影，仅实际变化或本地校验信息变化的条目标记脏分片；无脏分片时跳过缓存保存。启动校验后的可重建缓存、业务写入后的指纹与脏分片均 5 秒防抖持久化，手动刷新仍等待缓存保存；指纹保存合并外部改动并保留本应用待写记录。格式转换删除源图前同步保存指纹与分片；切库或清除库配置等待旧库写锁与旧缓存落盘。服务端记录缓存恢复、修改指纹读取、文件夹树读取、目录枚举、属性校验、元数据重读与缓存落盘的耗时及数量，启动总耗时不含后台缓存保存。
- 过滤、计数、排序在内存完成，目录概览和排序视图按库版本缓存，翻页仅切片；删除条目保留在索引供回收站使用。目录 `count` 为直接成员数，`totalCount` 含子孙。
- 「操作时间」取条目 `lastModified`，「修改时间」取原文件 `mtime`，库根 `mtime.json` 仅用于变更检测。新建/追加沿用资源列表排序，确认列表按实时条目摘要排序并接收库增量变化。
- 库与结果各自记录增量变更，游标含服务启动标识；过期、重启或整体失效时返回完整快照。

## API 约定（/api/eagle）

完整参数以 `schemas.ts` 和路由代码为准，前端通过 Hono RPC 推导类型。下表 `{a,b}` 表示同一前缀下的多个接口：

| 方法       | 路径                                                                                                                       | 用途                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| GET        | `/overview`、`/folders`、`/items`                                                                                          | 目录、计数、keyword 文件名搜索与 offset/limit 分页；未指定目录为全部   |
| PUT        | `/folders/:id`、`/items/:id`                                                                                               | 目录名称/描述、条目标题/归属                                           |
| DELETE     | `/items/:id`、`/items/:id/purge`                                                                                           | 移入回收站、彻底删除                                                   |
| POST       | `/items/:id/restore`、`/trash/purge`、`/unclassified/trash`                                                                | 还原、清空回收站、未分类批量移入回收站                                 |
| POST       | `/refresh`、`/items/:id/add-to-gallery`                                                                                    | 刷新索引、导入输入图库                                                 |
| GET / POST | `/items/:id/detail`、`/items/:id/media-edits`                                                                                   | 当前媒体详情、按内容版本校验的媒体编辑覆盖                                 |
| POST / GET | `/items/:id/media-edits/jobs`、`/items/:id/media-edits/jobs/:jobId`、`/items/:id/media-edits/jobs/:jobId/cancel` | 启动编辑保存任务、查询进度与结果、取消未提交的任务 |
| GET        | `/items/:id/{thumbnail,file,preview,video-contact-sheet}`                                                                  | 缩略图、原文件、只读大图、视频联系表（缺失或失效时生成并保存）         |
| GET        | `/conversion/candidates`                                                                                                   | 全库分页候选；`snapshot=true` 返回完整候选 ID 与摘要                   |
| POST       | `/conversion/items/:id`                                                                                                    | 单张转换或源图删除重试                                                 |
| GET        | `/organize/prepare`、`/organize/status`、`/organize/task`、`/organize/queue`、`/organize/failed-items`                     | 准备、状态、任务、队列与失败详情                                       |
| POST       | `/organize/task`、`/organize/task/{append,pause,resume,sync-standards,retry-failed,skip-failed,classify-successful,clear}` | 创建、追加、执行控制、标准同步、失败处理、仅保留成功项、清空           |
| GET        | `/organize/results`、`/organize/results/:itemId`、`/organize/results/changes`                                              | 分页、详情与增量结果                                                   |
| POST       | `/organize/results/reconcile`、`/organize/results/confirm-batch`                                                           | 缺失条目校准、批量确认                                                 |
| POST       | `/organize/results/:itemId/{confirm,trash,skip,retry,clear-classification}`                                                | 单项确认、移入回收站并跳过、跳过、重做、清除归属并按推荐标题改名后跳过 |

- 响应为 `{ success: true, data }` 或 `{ success: false, error: { code, message } }`；校验失败 400，任务身份冲突 409 / `TASK_CHANGED`，存储错误保留原错误码。GET 不修改任务或计数，校准通过 POST 显式执行。
- 条目 ID 满足 `^[A-Za-z0-9]+$`，文件路径从可信索引获取。媒体接口支持 ETag，原文件支持 Range；`contentVersion` 由库路径、原文件名、`lastModified` 派生，用于 URL 的 `v`、ETag 和回退缩略图缓存。无版本或旧版本 URL 必须重新验证。
- `/overview`、`/folders`、`/items` 按 `mediaType=image|video` 统一过滤；`/trash/purge`、`/unclassified/trash` 同样限制批量范围，未传参数保留全库语义。
- `/overview` 的 `trashSize` 与 `/trash/purge` 的 `size` 为当前范围的原文件累计字节数（基于索引元数据，不含缩略图等附属文件），清空确认和成功提示同时展示数量与大小，统计不受搜索或分页影响。
- 新建携带 `expectedTaskId`（无任务为 null），其他任务修改携带 `taskId`，命令锁内先校验身份。准备、新建和追加的 `mediaType` 默认 image；旧字段 `imageCount` 表示当前类型的可处理总数。

## 浏览与前端同步

- 默认图片（含 GIF），图片/视频按扩展名集合过滤。媒体类型保存于 `eagle_media_type`，两类目录分别存于 `eagle_selected_folder_image` / `eagle_selected_folder_video`；旧 `eagle_selected_folder` 迁移为图片目录记录，新记录写入后删除旧键。切换类型恢复各自目录，失效时回到「全部」，保留搜索排序并重查第一页和目录计数；资源每页 100 条。
- 文件名搜索覆盖当前目录全部资源，忽略首尾空白和大小写，空白分隔的关键词须全部匹配；服务端先过滤再排序分页。搜索不持久化，切目录、排序、翻页、刷新时保留，改词回到第一页；资源数量显示匹配数，目录树保留完整计数。
- 网格右键/长按菜单在修改文件夹与删除操作之间提供下载图片/视频，下载原文件，使用与预览一致的完整 `name.ext` 文件名；回收站条目也可下载。
- 隐藏空目录仅影响展示：按当前类型递归总数判断，保留有资源子孙的父目录、虚拟导航和完整归档/整理目录数据；此选项默认开启并持久化。未分类批量移入回收站和回收站批量删除仅作用于当前媒体类型。
- 普通目录可新建/追加整理；「全部」「未分类」「回收站」仅在有未完成任务时提供继续入口，可恢复、处理、确认已有任务，无需重新配置接入点。特殊视图禁止添加且不查询范围准备数据，提交时再次校验真实来源目录。
- 图片大图预览提供完整文件名与移入回收站操作（无需二次确认，成功后关闭并刷新，失败保留预览）；右键删除仍需确认。视频独立预览弹窗显示完整文件名、大小、宽高分辨率和视频时长（加载元数据后优先使用实际视频尺寸，时长显示在分辨率后，超过一小时显示小时）；播放器倍速选择保存在 localStorage 的 `eagle_video_playback_rate`，首次默认 1 倍，打开其他视频、切回视频模式或刷新后沿用。底部可切换视频/联系图，首次默认视频，选择保存在 localStorage 的 `eagle_video_preview_mode`，下次打开其他视频或刷新页面后沿用。联系图模式立即请求接口，缺失或失效时生成并保存，提供加载状态和失败重试；切换为联系图或关闭弹窗时卸载播放器；联系图模式通过不播放的视频元素预加载元数据，以显示实际尺寸和时长。
- `libraryRefresh.ts` 合并主动刷新与 SSE，整理弹窗打开期间记脏、关闭后补拉；`refreshQueue.ts` 串行合并刷新和失效补拉。请求序号/版本保护防止旧响应覆盖切库、切类型或新查询。
- `EaglePreferenceDocument` 共享加载、订阅和串行保存目录展开/手动历史，保留 revision 冲突检测及加载中操作重放。

### 媒体编辑预览与覆盖

- 保存入口为 `MediaEditSaveButton`，接收显式 `operations` 操作列表，预览组件将编辑状态转换为操作；服务端由 `library/media-edit.ts` 与 `media-edit-jobs.ts` 编排版本复核、备份、进度、取消和提交回滚，`media/edit.ts` 编译并执行编辑操作。同步保存与异步任务共用 `schemas.ts` 的 `eagleMediaEditSaveSchema`，请求为 `{ contentVersion, operations: [{ type: 'rotate', degrees: 90 }] }`；操作列表有序、非空且最多 32 项，旋转角度支持 90/180/270，未知操作与多余字段拒绝。当前仅实现旋转，相邻旋转合并为一次处理（抵消时移除），一次编码后统一验证与保存；新增操作须扩展 schema 与对应图片/视频处理器，保留列表顺序，不能静默忽略未实现的操作。
- 资源浏览与整理普通/快速确认的图片全屏预览沿用图片旋转工具；视频全屏弹窗提供左右 90° 旋转，旋转后按可用空间重新适配。播放控件与视频画面独立，旋转时控件保持水平；首次点击显示控件，之后点击视频画面或所在行的两侧空白可播放/暂停，支持进度、音量与倍速调节，播放器聚焦时可用空格/回车播放暂停、左右方向键快进/后退 5 秒；点击播放行外的空白关闭预览，保存期间禁用。联系图只是视频的派生预览，不提供旋转覆盖。
- 非零旋转角度（90°、180°、270°）显示「覆盖原文件」，只保存旋转，不保存图片预览的缩放、平移或翻转。请求携带预览的 `contentVersion`；图片整理预览打开时查询当前详情，资源浏览预览保留打开时的列表快照，防止排序或刷新换错条目。
- 生成和验证在库锁外串行进行；提交经库写锁复核库、索引、完整元数据、原文件与缩略图，拒绝链接和越界路径。先独立复制原文件及原始元数据/缩略图为新的 `isDeleted` Eagle 条目，再替换当前条目的文件和缩略图并同步保存指纹、分片。保留当前 ID、名称、归属、其他元数据和修改时间排序；原始文件可从 **Eagle 回收站** 还原，整理结果与进度继续绑定当前 ID。
- 图片按 EXIF 方向归正后旋转，常用栅格格式保留扩展名，其他可解码静态图片（含 HEIC/HEIF）输出 PNG；不保证非时间类 EXIF/HDR 保留，动画/多页图片拒绝覆盖，避免静默丢帧。视频输出 H.264/AAC MP4，应用原显示方向和像素比例，再进行指定旋转，清除输出旋转元数据，保持全部音轨，必要时补齐偶数尺寸。
- 旋转输出通过随包携带的 `exiftool-vendored` 复制可读取的内部日期、时区和子秒标签（含 EXIF/XMP/IPTC、PNG、QuickTime 等），保持原始标签组和值，不推断时区、不复制旧方向、尺寸或时长；重新读取并逐字段验证，输出格式不支持或值不一致时拒绝覆盖。HEIC/HEIF 的时间字段从原文件读取，不依赖已经去除元数据的解码中间图。输出原文件与回收站备份恢复原文件系统修改/访问时间，Windows 用隐藏 PowerShell 的 .NET API 恢复创建时间并校验（毫秒级容差）；回滚同样恢复。Eagle 原有 `mtime` 和创建类字段保留，`lastModified` 继续记录本次操作，以驱动内容版本和增量刷新；系统状态变更时间 `ctime` 不作为可保留的媒体日期。
- 保存期间限制重复保存、关闭和切换预览；视频覆盖保存通过内存任务显示百分比与处理阶段，转码按 FFmpeg 输出时间占实际时长计算 0～90%，校验为 92%，备份按复制字节数推进 95～98%，最终提交为 99%，完成后才为 100%，不表示剩余耗时。排队、转码、校验和备份阶段可取消，停止相关子进程与复制流后清理临时文件、保留原文件；最终替换与索引提交期间暂停取消，完整提交或回滚。组件卸载时尝试取消未提交任务，查询断线时保留任务身份并重试；任务结果在完成后保留十分钟供查询，不落盘。视频转码允许最多 24 小时。成功后刷新内容版本、尺寸和缩略图；原联系图根据源文件指纹失效并按需重新生成。确认页收到库变更后重新拉取详情，保留旧详情直至新响应返回，避免卸载在途视频预览。
- 提交失败尝试恢复文件、缩略图、元数据及索引；回滚失败保留回收站原文件备份并报错。改格式后只有在提交持久化完成后才清理确切旧文件，清理失败返回警告；未知旁文件不删除。媒体编辑保存不建立持久化任务或进程中断后的自动恢复队列。

## 整理流程

图片与视频共用单个任务，任务保存 `mediaType`（旧任务默认 image），禁止混合追加；切换标签可继续已有任务，完成或清空后才能添加另一类型。GIF、HEIC/HEIF 不参与图片分类。

### 分类模式与步骤

| `classificationMode`         | 来源 / 分类标准                                                            | 写库方式                                                   |
| ---------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `global`（默认，旧任务兼容） | 当前普通目录；全库有描述的目录为标准                                       | 分析后手动确认分类与可选改名，保留低质判断                 |
| `subfolders`                 | 当前普通目录；其全部层级有非空描述的子目录，不含自身，保留完整路径和优先级 | 手动确认；不判定/展示低质，丢弃模型或旧结果的 `lowQuality` |
| `recursive-rename`           | 当前目录及全部子孙中需要改名的资源，无需目录描述                           | 自动仅改名，保留归属与低质判断，不进入待确认               |

- **01 待添加**：新建选择模式、数量、并发与压缩参数；分类无有效标准时禁止创建，仅重命名允许空标准但必须有有效来源，禁止扩大到全库。未完成任务可跨普通目录追加，沿用任务模式、标准和参数，按 Eagle ID 排除队列与本轮结果（含已确认/跳过项），串行更新时再次去重。子目录任务的目标范围始终绑定创建目录，标准差异检测与同步也使用该范围；仅非运行、未结束任务可同步标准，仅重命名不检测标准差异。仅重命名默认处理全部候选，`previewItems` 只预览前 50 条未入队项，不限制实际数量；目录、排序、模式或转换变化后刷新准备数据。
- **02 处理中**：支持暂停派发、恢复、失败重试/跳过、清空；执行器限制并发与间隔，连续失败或落盘异常时暂停并通知。暂停可仅保留成功项进入确认。清空中止请求和后续处理，不撤销已写库修改。
- **03 待确认**：仅展示分析成功项；普通模式选择推荐/手动目标和标题，快速模式按首选推荐确认，疑似低质与未分类默认置顶。两种视图均可手动置顶一个待确认分堆，通过与手动选择文件夹共用的可搜索树状弹窗选择首选推荐类别、疑似低质或未分类，显示剩余数量；仅有待确认项的类别可选，无待确认项的父目录仅展示层级，搜索隐藏的选择不能提交；确认选择后切换为分类排序并选中该分堆首项，优先于默认特殊类别，其他分堆保持原顺序，支持取消置顶，同一任务内通过 sessionStorage 保留选择，与右侧确认目标的置顶独立。清除分类（A）清空全部目录归属、不采用推荐分类，同时使用推荐标题改名（不受标题勾选影响，仍遵循无需改名规则），写库成功后跳过结果。支持不处理（S）、确认（D）、移入回收站、重做。递归仅重命名隐藏本步骤和确认入口。执行完且待确认、失败项均处理后进入 `done`。
- 子目录确认默认候选包含绑定目录的全部层级子目录（可无描述/历史，不含自身），置顶优先，其余按推荐顺序、手动使用次数、目录树顺序排序并按路径去重；首次使用也记录历史，不混入全库其他历史。手动选择仍可使用全库目录或置顶范围外目录；目录名称搜索保留匹配父路径，被过滤隐藏的选择不能提交。追加来源不改变默认候选范围。
- 确认页通过增量接口合并/移除结果并本地排序，进入页面或任务身份变化时显式校准缺失项；reset 替换列表，仅接受响应后推进游标。任务切换、卸载及乐观操作后的过期响应不得覆盖当前状态。

### 模型标题与任务恢复

- 分类响应为标准内 0～3 个不重复 `folderPaths`（空数组合法），需改名时另含 `title`；全局要求 `lowQuality`，子目录丢弃该字段。分析仅存结果，确认才替换 `folders[]`。仅重命名使用 `{ title, lowQuality }`，忽略分类建议，复用 `confirmation.ts` 的仅改名计划，不传 `folderIds`，服务端拒绝清除分类命令。
- 当前名称按 `_` 分段，末段模型名与当前接入点首个英文词匹配时跳过改名（忽略大小写、版本及同系列变体，兼容旧缩略标识）。例如 `_gemini3.7` 匹配 `gemini-3.8-flash-high`，`_gpt5.6` 不匹配 Gemini。新后缀去除 provider 路径，取首个英文词与版本数字，将版本 `-` 转为 `.`，如 `claude-3-7-sonnet` → `claude3.7`。
- 候选筛选、执行/重试和确认共用该规则。无需改名时提示词省略标题要求、忽略意外标题，保存 `needsRename: false`；确认不提交改名且后端重新检查当前名称、模型和结果，旧结果同样处理。仅分类成功不依赖标题，跳过后仍计入成功数；仅重命名项入队后若已匹配模型，直接完成而不再调用模型或改名。
- 单项执行绑定接入点快照，提示词、实际模型与后缀保持一致，配置变更不影响在途请求。标题 120 字符上限需预留后缀空间；提示词预览支持分类并改名/仅分类两版。
- 自动改名先持久化 `success` 建议，再写库并持久化 `confirmed`，待确认数始终为 0；写库失败存 `failed` 并计入暂停阈值。启动遇到遗留 `success`（含旧版待确认结果）暂停任务，恢复时复用建议且重新检查名称，避免再次调用模型或重复改名；库已改名但状态未保存也按此恢复。强制清空检查执行轮次，阻止未开始的写库并等待在途写库收尾后删记录。

## HEIC/HEIF 格式转换

图片整理提供独立的全库转换入口，不随当前目录变化。打开弹窗/切库时查询候选：查询中隐藏，无候选隐藏，查询失败保留供重试；本次转换完成后保留入口展示结果，下次打开重新检查。视频标签不查询或展示转换。

- 查询全库未删除 HEIC/HEIF（扩展名忽略大小写），每页 50 条；候选与批量快照按原目录树顺序（父先于子、同级原顺序）排序，多归属按最靠前目录定位，无有效归属放最后，同目录保留条目顺序。列表/失败项携带完整归属路径。
- 支持单张、全库转换及单项/全部失败重试。批量取候选快照，最多 3 张并发，解码编码可重叠、提交受库写锁保护；逐项失败不阻断后续。关闭、卸载、切库停止派发，在途请求各自完成；失败详情仅存本次弹窗。已提交项（含源图保留警告）移出候选，源图警告留在失败列表；批次结束/停止并等待在途请求后统一补拉并刷新可整理数量，由用户加入任务。
- 只读大图按需解码为全尺寸 WebP，失败回退 Eagle 缩略图，不修改原图或元数据。
- **解码**：`media/heic.ts` 使用 `heic-decode@2.1` 的 libheif WASM 与 sharp，输出完整尺寸、质量 90 的有损 WebP，不使用分类压缩设置，不承诺全部 EXIF/HDR 保留。libheif 已处理容器 `irot`/`imir`/裁剪，raw 像素不再 EXIF 自动旋转。校验顶层 BMFF、序列品牌/`moov` 和 libheif 原始顶层图片数为 1（不能只看可能跳过错误 handle 的解码数组）；多图、序列、损坏或不支持编码报错并保留源图。
- **替换**：请求绑定 `libraryId`，可信源路径限定在对应 `images/<id>.info/`，不跟随符号链接/junction。锁外解码编码，`wx` 创建唯一临时文件、同步写盘并从实际文件完整重新解码；锁内复核库、条目、完整元数据及源属性。硬链接独占放置目标，已存在或不支持硬链接即失败并保留源图。原始 metadata 仅更新 `ext`、`size`、实际宽高和 `lastModified`，其余字段保留；metadata 和 WebP 文件 `mtime` 保持原值以免改变排序。
- **删除/回滚**：WebP 验证、原子元数据写入、索引/指纹/分片持久化完成后才删除确切源图，不删除 `.info`、缩略图或未知旁文件。提交失败回滚元数据和索引持久化状态，仅清理本次独占创建且身份/内容一致的目标和确切临时文件；外部修改或回滚失败保留源图并报错。
- **源图删除重试**：失败返回 `sourceRemoved=false` 与警告；最多 1000 个内存凭据，重试复核版本、路径、源属性、完整元数据和 WebP 哈希后仅删源图，不重压缩。重启、凭据失效或再次编辑后需人工检查条目目录；转换无持久化任务/队列或启动恢复。

## 视频整理

- `media/video-layout.ts` 定义采样规则，`media/video-metadata.ts` 用 FFmpeg 读取输入时长和首个视频流尺寸，供联系表与旋转验证共用；只映射视频流并输出零时长的 null，不转码或扫描整个视频。优先读取视频流 DURATION 标签，否则使用容器时长（FFmpeg 日志精度为百分之一秒）；无法读取有效时长或尺寸时报错。`media/video.ts` 用 FFmpeg 抽帧、sharp 合成。每视频仅上传一张质量 60 的 WebP 联系表，不上传原视频，不受图片压缩开关影响；分类手动确认后才改目录/名称，仅重命名仍自动执行。
- 独立视频提示词与前端预览共用，逐视频注入实际时长、间隔、帧数、行列和时间位置；生成与提示词使用同一采样数据，复用已有联系表时直接读取保存的时长和采样信息，不再探测视频。模型结合多个时刻，不混淆采样间隔/原视频帧率，不推断音频、未采样情节或精确动作速度；预览说明运行时注入字段，不填虚构数值。

| 时长              | 采样间隔                                   | 单帧长边上限 | 最大布局 |
| ----------------- | ------------------------------------------ | ------------ | -------- |
| 0 < 时长 ≤ 16s    | 1s                                         | 400px        | 4×4      |
| 16s < 时长 ≤ 32s  | 2s                                         | 400px        | 4×4      |
| 32s < 时长 ≤ 64s  | 4s                                         | 400px        | 4×4      |
| 64s < 时长 ≤ 256s | 4s                                         | 300px        | 8×8      |
| > 256s            | 8s、16s、32s…按 2 的幂向上取整，最多 64 帧 | 300px        | 8×8      |

- 从 0 秒按间隔采样，时间严格小于时长，逐行从左到右排列；32 帧以内使用 4 列（不足 4 帧时按实际帧数），超过 32 帧使用 8 列，行数按实际帧数向上取整，最多 8 行，例如 9 帧为 3 行×4 列、32 帧为 8 行×4 列。保持显示比例、处理旋转/像素比例、不裁剪，外缘与帧间 4px 白边、末行空位白色，提示词忽略白边/空位。长视频输入前 seek，避免从头解码。
- 联系表定位为视频长期预览资源，保存在条目 `.info/linai/` 子目录，独立于 Eagle 自身缩略图和整理任务；改名、改分类、清空任务、复制或搬迁整个库时保留，彻底删除条目时随 `.info` 一起删除。启动扫描和普通视频列表不读取旁文件，仅分类或请求联系表时按需读取。
- 配套 JSON 保存结构/生成规则版本、原视频大小与 mtime、时长、采样间隔/帧数/行列和 WebP 的 SHA-256，不存视频名称或绝对路径。`GENERATOR_VERSION`（当前 2）仅记录新生成联系表的规则版本；`MIN_REUSABLE_GENERATOR_VERSION`（当前 1）控制旧联系表的复用下限，手动提高后，低于该版本的联系表在下次读取时重新生成，旧联系表复用时保留原布局。源文件变化、结构版本不受支持、旁文件缺失或损坏时仍重新生成。库写入经 library 门面与写锁，抽帧在锁外完成，提交时重新校验库、条目及源文件；图片与 JSON 分别原子替换，校验值防止复用中断后不匹配的配对，不修改 Eagle 元数据或索引指纹。
- 请求按库路径与条目 ID 去重，本地解码串行；子进程参数数组、隐藏 Windows 窗口、单命令 60s 超时，清空任务取消抽帧但保留已保存的联系表。失败进入既有重试/跳过流程。
- `GET /items/:id/video-contact-sheet` 供确认页与预加载查看 AI 同款联系表；普通确认点击联系图打开共用视频预览弹窗，可切换视频/联系图并沿用已保存的模式，详情提供原文件扩展名与内容版本。处理中使用 Eagle 单帧缩略图，避免等待项提前解码。

## 维护约束与修改指南

- **文档范围**：模块设计、数据流、接口契约、安全边界及有参考价值的维护约定变更时同步更新本文档；合并重复说明，不追加变更流水账。不要把过细或不重要的样式内容（如间距、颜色、控件宽度、排列细节或 Tailwind 类名）写入文档，避免膨胀，保持简洁易读；影响功能、可访问性或媒体处理正确性的约束应保留。
- **写库边界**：经 `library/index.ts` 门面和 `withLibraryMutation` 写锁，其他模块不得直接写库或访问可变索引。批量按 ID 返回逐项结果，仅确认成功项，成功项收尾不受后续失败影响；改名失败尝试回滚，物理删除失败保留索引。库写入与结果保存不是事务，写盘失败不得当作条目不存在。
- **任务与确认**：`mutateTask` 串行读改写，`transitions.ts` 统一阶段/计数，缓存仅在落盘成功后发布；部分失败由后续命令、执行收尾或启动恢复校准。单张/批量共用 `confirmation.ts`，显式 `folderId` 优先于快照路径且必须存在，重复确认不写库/扣计数，区分索引不可用与条目缺失。
- **前端职责**：`useClassifyTask` 管准备，`useConfirmResults` 管结果，`useConfirmSelection` 管选择，`useConfirmSubmission` 管提交，`useManualFolders` 管历史；UI 负责展示，命令放 hooks/store。`submissionQueue.ts` 按任务身份串行单项/批量提交，失败只恢复对应项；`statusModel.ts` 派生乐观计数，服务端决定阶段，提交后校准。普通/快速确认共用 `StepConfirm/utils/list.ts` / `sort.ts`，删除并跳过使用单个 trash 命令。
- **字段与排序**：列表字段修改 `shared/eagle/types.ts` 的 `EagleItem` 和 `library/query.ts` 的 `toEagleItem`，需缓存时同步索引类型、`scan.ts` 与旧缓存默认值；排序修改 `EagleSortBy`、query 和 Toolbar，兼容旧偏好。
- **接口与配置**：API 在 library/organize 路由链式注册、zod 校验，前端对应 api 文件封装；请求响应由 Hono RPC、设置由服务端 schema 推导，仅实际共用的契约/纯函数放 shared，旧兼容留存储边界。设置放 `settings/`，表单保存失败向上传递；展示偏好用 localStorage，便携业务偏好走通用存储。
- **媒体与发布**：目录纯逻辑放 `library/folders.ts`，媒体放 `media/`，缩略图缓存统一 `media/cache.ts`；原文件接口不要使用整读 Buffer 的 `common/static/serveImage`。`heic-decode` / `libheif-js` / `ffmpeg-static` / `exiftool-vendored` 保持 tsup external 和完整生产包，WASM 内嵌无需联网；安装配置允许 ffmpeg-static 二进制脚本，便携包携带解码器与 ExifTool 平台二进制。发布前手动验证 Eagle 刷新和便携兼容性。
- 代码完成后仅运行 `npx tsc --noEmit`，不运行 build 或 eslint；按项目约定格式化变更。
