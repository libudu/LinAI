# 远程互联

独立 EasyTier 普通进程管理一个活动房间。房主创建房间后，添加或选择权限组，生成对应的完整邀请；成员粘贴邀请加入。权限组、邀请、连接、撤销统一在「远程互联」，Eagle 只负责资源授权及只读浏览。首版成员可选择房主的 Eagle 本地库；需要提供库的一方先创建房间。不实现房间信令服务器、账号、短码、聊天或公开大厅。

## 运行与授权

- `core.ts` 生成固定限制的 TOML，通过参数数组启动核心及 CLI。双方 `no_tun` / `use_smoltcp`，不安装服务，不改路由、DNS、hosts、代理、防火墙或 UPnP。Windows 防火墙及受管网络仍可能限制连接。
- 管理 RPC 使用临时的 `127.0.0.1` 端口，核心另有回环白名单；清除子进程的 `ET_*` 环境变量，防止外部参数覆盖隔离设置。Windows 隐藏父进程监视器保证 Node 异常退出后关闭该核心，不影响其他 EasyTier 进程。
- 房主使用随机网络名及 256 位主密钥。主密钥不进入邀请。通过 EasyTier Secure Mode CLI 为每个权限组签发禁止并发复用、禁止代理其他网段及中继的凭据。应用不再设置邀请有效期；底层 CLI 强制要求正数 TTL，内部统一设至 9999 年末，仍支持主动撤销。旧邀请保留原有效期，需要重新生成才能使用新规则。
- 邀请含房间名、房间 ID、固定分配的成员 IP、必要节点信息、接入凭据、Eagle 请求能力和房主 TLS 证书。邀请等同接入凭据，只交给使用对应权限组的成员。重新生成先撤销旧凭据，旧 Eagle 会话立即终止；网络撤销通过 EasyTier 传播，可能存在延迟。
- 房间、授权与会话由后端内存持有，导航、页面刷新、SSE 重连不销毁；退出房间、核心退出或重启 LinAI 后需要重新连接。进程运行期间所需临时配置在 `data/interconnect/active.toml`，关闭时删除，不在通用设置返回。
- 公共共享节点只提供 EasyTier 发现和中继，不是房间服务器。节点必须支持 Secure Mode 临时凭据，节点运营方可能限制中继。高级设置默认收起，支持 TCP / UDP URL；邀请携带房主选择的节点，加入方不覆盖。
- 连接状态每 3 秒读取内置核心 `peer --output json` 的展示行数组，以房主/成员对应行的 `cost`（`p2p` / `relay(n)`）显示直连或中转，未知值显示待确认。本机与公共节点不计为房间成员在线；路由信息仅用于状态展示，不作为共享授权依据。
- 加入时填写成员名称，名称与随机生成的本机用户 ID 保存在 `data/interconnect/identity.json`，改名、换网或重启不改变 ID；删除本机数据后会重新生成，复制这份数据也会复制身份。用户 ID 用于记录归并，不是认证凭据。
- 成员经固定信任房主证书的 TLS 通道携带邀请能力登记，并每 3 秒同步在线成员。登记与 Eagle 审批独立；权限组登录历史由私有 DocumentStore 持久化到 `data/interconnect/member-history.json`，按权限组与用户 ID 归并，保存最新名称、房主分配的虚拟 IP 与服务端登录时间；普通同步不刷新登录时间，重新加入或断线超过 15 秒后重新登记才更新。历史仅在房主的本地管理界面展示，没有记录的权限组不展示历史区域。

## Eagle 与网络边界

- `entry.ts` 单独创建 `127.0.0.1:18243` HTTPS 服务，只挂载共享协议白名单及 `POST /api/interconnect/member/login` 成员登记接口，绝不调用主服务的 `app.fetch`。登记必须校验当前邀请能力，只返回在线成员名称及虚拟 IP，不返回登录历史或权限设置。核心固定转发到这个端口，不能转发主服务端口或其他本机服务。
- 双方 ACL 的入站、出站、转发链默认全部 Drop，覆盖 TCP、UDP、ICMP 等 IP 流量。房主仅接受目标 `10.127.62.1:18243` 的 TCP，出站仅允许该共享端口的响应；成员仅能向房主此端口发 TCP。转发链始终拒绝，RPC 也不能经虚拟网络访问。
- `https.ts` 为每次房间请求固定信任邀请中的房主证书，校验 TLS、有效期及回环地址。即使其他成员伪造主机名或虚拟 IP，也不能获得共享凭据。拒绝重定向，不转发浏览器 Cookie 或任意请求头。
- 网络接入凭据不等于 Eagle 授权。成员主动选择远程库后，用独立的强随机能力向房主请求；房主明确批准，才签发仅在双方后端内存保存的 Bearer 会话。旧八位邀请码不再是网络接入凭据。
- 复用 `eagle/sharing` 的只读接口、目录/条目过滤、流式 Range、心跳与撤权中断。文件夹设置仍在 Eagle，`everyone` 与指定权限组授权取并集；未分类、回收站、编辑、整理、系统设置及其他模块不开放。
- 复用 `eagle-sharing` 的原有记录作为权限组，不复制权限表；旧 `folderSharingCode`（缺失时回退旧邀请码）保持不变。改名和生成新邀请不迁移权限。删除权限组保留文件夹授权记录，新权限组生成键时避开这些遗留键，防止意外继承旧权限。

## 发布与验证

运行资源固定在 `dist-template/runtime/easytier/`，开发和发布启动仅校验清单 `files` 的 SHA-256。包内保留核心、CLI、许可、来源及修改/构建说明，不依赖运行时下载。

对应源码输入位于 `release-resources/easytier/EasyTier-2.7.0-linai.6487a5e-source.zip`，包含修改后的固定提交源码、依赖 crate/git 源码及运行库许可；原始归档保持不变。运行时清单 `correspondingSource` 记录文件名、大小与 SHA-256，将项目内源码与核心版本/提交关联；不参与启动文件校验。`post-build.ts` 在发布前验证两类文件，重建 `dist/runtime/easytier/` 清除旧源码归档，不再复制源码归档到仓库根目录，也不作为发布附件上传；private/public 复用项目内的同一份源码，`dist` 与主 ZIP 都不含源码 ZIP。

仓库通过 https://github.com/libudu/LinAI/releases 发布；工作流仅上传主包，在发布说明中链接到同一 tag 下项目目录中的源码文件。包内 `SOURCES.md` 指引用户按 LinAI 版本 tag 查找项目内源码并按清单验哈希。按 GPLv3 6(d)（LGPLv3 引用），分发程序时仍需维持接收者可免费访问的对应源码位置及明确获取指引；仅保存在接收者无法访问的本地目录不足以提供源码。更新核心时必须同时更新对应源码、构建说明及清单，不可复用旧源码归档冒充新核心源码。

禁止用官方 Windows ZIP 中的 Npcap `Packet.dll` 填充缺失依赖。官方 v2.6.4、v2.7.0 预发布和调研时 nightly 的 PE 导入表都存在该静态依赖；便携核心必须使用不含抓包/TUN 功能的独立裁剪成品。这里的核心版本以发布清单为准，不能按 main 文档推断旧版本能力。

代码验证仅在完成后运行 `npx tsc --noEmit`，不构建 LinAI、不运行 eslint 或视觉验证。发布前仍需真实双机验证直连/中继、无管理员账户、浏览器刷新、Range、撤权及异常退出清理；仅类型检查不能证明这些网络行为。
