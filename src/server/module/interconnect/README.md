# 远程互联

独立 EasyTier 普通进程管理一个活动房间。房主创建房间后，添加或选择权限组，生成对应的完整邀请；成员粘贴邀请加入。权限组、邀请、连接、撤销统一在「远程互联」，Eagle 只负责目录授权及只读浏览。成员确认连接后，将 Eagle 切换为房主的远程资源库，无需房主二次审批；需要提供库的一方先创建房间。不实现房间信令服务器、账号、短码、聊天或公开大厅。

## 运行与授权

- `core.ts` 生成固定限制的 TOML，通过参数数组启动核心及 CLI。双方 `no_tun` / `use_smoltcp`，显式关闭 `bind_device`，让操作系统选择外层连接源地址并兼容本机回环连接；不安装服务，不改路由、DNS、hosts、代理、防火墙或 UPnP。Windows 防火墙及受管网络仍可能限制连接。
- 管理 RPC 使用临时的 `127.0.0.1` 端口，核心另有回环白名单；清除子进程的 `ET_*` 环境变量，防止外部参数覆盖隔离设置。Windows 隐藏父进程监视器保证 Node 异常退出后关闭该核心，不影响其他 EasyTier 进程。
- 双方使用 EasyTier 普通模式，显式关闭 `secure_mode`、保留网络加密。房主每次创建房间生成随机网络名及 256 位房间密钥，成员通过邀请获得同一密钥入网，不再签发或撤销 Secure Mode 临时凭据。普通模式无法限制成员并发复用网络密钥，也不能单独撤销成员的入网能力；彻底移除旧成员需要关闭并重建房间，让其他成员使用新的邀请。
- 邀请采用 `linai-room:v2:`，含房间名、房间 ID、分配的成员 IP、必要节点信息、房间网络密钥、独立的权限组 Eagle 请求能力和房主 TLS 证书，不设置有效期。邀请只交给使用对应权限组的成员。重新生成或撤销时，旧 Eagle 请求能力及共享会话立即失效，但旧网络密钥仍可用于当前房间的网络连接。双方需更新 LinAI；旧 v1 安全模式邀请明确提示房主重建房间、重新生成邀请。
- 每次发邀请都分配新的虚拟 IP，撤销后不在本房间复用，避免仍在线的旧节点与新成员冲突；单个房间最多累计签发 253 次邀请，用尽后需重建。IP 与路由只用于连接展示，不作为权限组认证依据。
- 房间、授权与会话由后端内存持有，导航、页面刷新、SSE 重连不销毁；退出房间、核心退出或重启 LinAI 后需要重新连接。进程运行期间所需临时配置在 `data/interconnect/active.toml`，关闭时删除，不在通用设置返回。
- 公共共享节点只提供 EasyTier 发现和中继，不是房间服务器。不再要求节点开启 Secure Mode，节点运营方仍可能限制中继。高级设置默认收起，支持 TCP / UDP URL；邀请携带房主选择的节点，加入方不覆盖。
- 连接状态每 3 秒读取内置核心 `peer --output json` 的展示行数组，以房主/成员对应行的 `cost`（`p2p` / `relay(n)`）显示直连或中转，未知值显示待确认。在线状态同时要求对应路由存在、成员登记成功且租约未过期；仅有路由、本机或公共节点不能算作房间成员在线，路由信息不作为共享授权依据。
- 房间成员列表标记房主角色，并展示各成员与房主之间的连接方式；连接方式随成员登记响应同步给加入方，不代表成员之间的连接。
- 创建或加入时填写你的名称，输入自动保存在浏览器 localStorage（`interconnect_member_name`），刷新后优先恢复；尚无前端记录时兼容读取后端上次使用的名称。创建或加入时提交的名称与随机生成的本机用户 ID 保存在 `data/interconnect/identity.json`，改名、换网或重启不改变 ID；删除本机数据后会重新生成，复制这份数据也会复制身份。房主名称也会展示在房间成员列表中。用户 ID 用于记录归并，不是认证凭据。
- 成员经固定信任房主证书的 TLS 通道携带邀请能力登记，并每 3 秒同步在线成员。登记与 Eagle 资源库连接独立；权限组登录历史由私有 DocumentStore 持久化到 `data/interconnect/member-history.json`，按权限组与用户 ID 归并，保存最新名称、房主分配的虚拟 IP 与服务端登录时间；普通同步不刷新登录时间，重新加入或断线超过 15 秒后重新登记才更新。历史仅在房主的本地管理界面展示，展开后前端每页最多显示 10 条，没有记录的权限组不展示历史区域；支持逐条删除历史，与成员登记共用房间命令队列，不撤销当前连接或删除下载日志，后续重新登记可再次记录。
- 应用层在登记租约内只接受同一邀请的同一用户与会话，避免转发邀请后成员身份和下载归属来回覆盖；原会话离线满 15 秒后才允许其他会话登记，切换时终止该权限组的旧共享会话。这不限制普通模式的网络层密钥复用，同一邀请不能供多个客户端同时入网，否则仍可能发生虚拟 IP 冲突。后台同步和手动连接资源库共用同一在途登记请求。登记返回 403 表示共享授权已失效，成员端显示已撤销、终止本机共享传输并停止自动登记，需退出房间后使用新邀请加入；网络超时等临时故障继续自动重试。

- 新邀请优先保留房主配置的所有节点，再利用剩余额度添加房主实际监听的 TCP / UDP 端口及最多两个局域网 IPv4 地址，用于同机与局域网直连，局域网地址优先 UDP；合并去重后最多十个地址，不因添加局域网地址截掉公共节点。房间重建后需要使用新邀请。
- 捕获核心 stdout / stderr，仅在内存保留最近三十秒内的去重错误，去除日志前缀并遮蔽密钥。连接探测与握手超时、等待握手时连接关闭、连续心跳失败、离线节点转发失败和端口转发的 DeadlineExceeded 单独保留为重试诊断，不作为房间警告；房主无成员在线时显示「等待成员加入」，成员加入或断线后先显示「正在连接房主」，连续三十秒未连接才提示检查房主、双方访问公共节点的网络及节点中转能力。成员连接持续失败或登记失败时，可展开查看连接地址及近期核心诊断；恢复连接后清除重试诊断。其他核心错误、RPC 故障与成员登记失败仍正常提示，核心启动失败或异常退出时保留完整的近期诊断。加入时同时检查本机 TCP 转发端口已监听，该探测也可能在尚无房主路由时触发一次转发超时。
- 独立核心必须同时启用 `smoltcp` 和 `socks5` 编译 feature，后者启动端口转发 gateway；原生 host 的 `proxy_enabled` 判定同时包含 `smoltcp`，让无 TUN 模式启动已有的入站 TCP 代理。应用不配置 SOCKS 监听，不启用原始 ICMP。

## Eagle 与网络边界

- `entry.ts` 单独创建 `127.0.0.1:18243` HTTPS 服务，只挂载共享协议白名单及 `POST /api/interconnect/member/login` 成员登记接口，绝不调用主服务的 `app.fetch`。登记必须校验当前邀请能力，只返回在线成员名称及虚拟 IP，不返回登录历史或权限设置。核心固定转发到这个端口，不能转发主服务端口或其他本机服务。
- 双方 ACL 的入站、出站、转发链默认全部 Drop，覆盖 TCP、UDP、ICMP 等 IP 流量。房主仅接受目标 `10.127.62.1:18243` 的 TCP，成员仅能向房主此端口发 TCP，请求规则启用连接跟踪以放行已有连接的回复；成员不开放新的入站连接。固定版本核心在 NAT 地址还原前检查出站 ACL，因此房主还放行内部 smoltcp 栈 `192.88.99.254:8899` 发往房间网段的 TCP 回复，随后仅按已有 NAT 映射还原为共享端口的响应，不增加对外端口。转发链始终拒绝，RPC 也不能经虚拟网络访问。
- `https.ts` 为每次房间请求固定信任邀请中的房主证书，校验 TLS、有效期及回环地址。即使其他成员伪造主机名或虚拟 IP，也不能获得共享凭据。拒绝重定向，不转发浏览器 Cookie 或任意请求头。
- HTTPS 连接池按房间固定目标与证书，复用 TCP/TLS 连接；媒体与心跳、成员登记、目录查询使用独立连接池，退出房间或核心退出时销毁，不能跨房间复用。
- 邀请确定成员所属权限组。成员确认连接房主远程资源库后，用邀请内独立的强随机能力验证权限组，直接签发仅在双方后端内存保存的 Bearer 会话，无需房主二次审批；可见内容仍由该权限组的文件夹授权决定。断开连接后远程库不可用，可在 Eagle 切回本地库。旧八位邀请码不再是网络接入凭据。
- 复用 `eagle/sharing` 的只读接口、目录/条目过滤、流式 Range、心跳与撤权中断。文件夹设置仍在 Eagle，`everyone` 与指定权限组授权取并集；未分类、回收站、编辑、整理、系统设置及其他模块不开放。
- 复用 `eagle-sharing` 的原有记录作为权限组，不复制权限表；旧 `folderSharingCode`（缺失时回退旧邀请码）保持不变。改名和生成新邀请不迁移权限。删除权限组保留文件夹授权记录，新权限组生成键时避开这些遗留键，防止意外继承旧权限。
- Eagle 文件夹下载沿用共享读取权限，新增的会话下载登记命令只允许记录授权目录，不开放远程写库。日志使用成员登记时绑定到邀请的用户 ID，私有保存在 `download-history.json`；权限组展开后的用户行通过本地管理接口查看，仅记录最初请求的目录。

## 发布与验证

开发资源固定在 `dist-template/runtime/easytier/`，发布时将同一份已校验资源放到 `server/easytier/`，启动优先读取发布目录，不读取旧的 `runtime/easytier/`。开发和发布启动仅校验清单 `files` 的 SHA-256。包内保留核心、CLI、许可、来源及修改/构建说明，不依赖运行时下载。

版本迁移默认更新程序文件，仅保留用户数据和正在运行的 Node 可执行文件，EasyTier 随 `server/` 更新。更旧的迁移程序虽然跳过 `runtime/`，仍会解压 `server/easytier/`，旧用户直接向原批处理拖入新包一次即可升级，无需先替换脚本。新版迁移会转交包内新版程序，额外校验并整体替换 `server/easytier/`；旧布局下的资源可保留，但不再被使用。迁移前应关闭 LinAI，避免核心文件被占用。通用规则和发布兼容检查见[迁移约定](../../common/migration/README.md)。

对应源码输入位于 `release-resources/easytier/EasyTier-2.7.0-linai-gateway1.6487a5e-source.zip`，包含修改后的固定提交源码、依赖 crate/git 源码及运行库许可。旧版对应源码可从 Git 历史获取。运行时清单 `correspondingSource` 记录文件名、大小与 SHA-256，将项目内源码与核心版本/提交关联；不参与启动文件校验。`post-build.ts` 在发布前验证两类文件，重建 `dist/server/easytier/` 并删除旧的 `dist/runtime/easytier/`，清除旧源码归档，不再复制源码归档到仓库根目录，也不作为发布附件上传；private/public 复用项目内的同一份源码，`dist` 与主 ZIP 都不含源码 ZIP。

仓库通过 https://github.com/libudu/LinAI/releases 发布；工作流仅上传主包，在发布说明中链接到同一 tag 下项目目录中的源码文件。包内 `SOURCES.md` 指引用户按 LinAI 版本 tag 查找项目内源码并按清单验哈希。按 GPLv3 6(d)（LGPLv3 引用），分发程序时仍需维持接收者可免费访问的对应源码位置及明确获取指引；仅保存在接收者无法访问的本地目录不足以提供源码。更新核心时必须同时更新对应源码、构建说明及清单，不可复用旧源码归档冒充新核心源码。

禁止用官方 Windows ZIP 中的 Npcap `Packet.dll` 填充缺失依赖。官方 v2.6.4、v2.7.0 预发布和调研时 nightly 的 PE 导入表都存在该静态依赖；便携核心必须使用不含抓包/TUN 功能的独立裁剪成品。这里的核心版本以发布清单为准，不能按 main 文档推断旧版本能力。

代码验证仅在完成后运行 `npx tsc --noEmit`，不构建 LinAI、不运行 eslint 或视觉验证。发布前仍需真实双机验证直连/中继、无管理员账户、浏览器刷新、Range、撤权及异常退出清理；仅类型检查不能证明这些网络行为。
